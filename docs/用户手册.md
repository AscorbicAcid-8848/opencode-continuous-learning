# OpenCode 持续学习插件用户手册

## 1. 这个插件做什么

插件把经过验证的长期事实按用户、全局和项目三个作用域保存，把可复用的操作流程保存为 OpenCode 原生 `SKILL.md`。它不会训练或修改模型权重。

插件安装在全局配置目录，因此对所有 OpenCode 项目生效。总开关默认开启，但自动复盘只有达到配置阈值时才会调用模型。

## 2. 在 OpenCode 中打开设置面板

安装并重启 OpenCode 后，在输入框键入：

```text
/learning-settings
```

它是原生 TUI 命令，会直接打开设置面板，不会向模型发送消息，也不会产生模型调用费用。另一个等价别名是 `/learning-config`。还可以打开 OpenCode 命令面板，搜索“持续学习设置”。

面板操作：

- 用方向键移动，输入文字可以搜索配置项，按回车选择，按 `Esc` 关闭当前面板。
- 每一行的当前值都在右侧以完整标签显示，例如 `[开]`、`[关]` 或 `[60,000]`。
- 面板只显示分类、中文配置名称和当前值，不显示内部英文配置键或长说明。
- 布尔开关选中后立即切换并保存；数值配置选中后输入新整数并提交。超出范围时会显示错误，不会改写原配置。
- 选择“恢复全部默认值”会先二次确认。它只恢复 14 个已知设置，不会删除 Memory、用户画像、项目 Memory、Skill 或复盘记录。
- 每次修改都原子写入 `~/.config/opencode/continuous-learning/config.json`。服务端插件在下一次提示注入、会话空闲检查或学习工具调用前自动重载，正常使用不需要重启。

正在运行中的某一次后台复盘不会被面板强制终止；新设置从后续插件动作起生效。面板是用户直接操作，因此修改设置本身不会触发 Agent 的写入权限确认。

## 3. 总开关

在 OpenCode 中打开设置面板：

```text
/learning-settings
```

- 选择“持续学习总开关”，按回车即可开启或关闭。
- 右侧 `[开]` 或 `[关]` 表示当前状态。
- 修改会立即保存并在后续插件动作中生效。

旧版 `/learning-mode` Slash 命令已经移除，避免与设置面板形成两个用户入口。底层 `learning_mode` 工具仍作为插件内部控制接口保留，但日常使用不需要手工调用。通过面板切换不经过模型；同时运行的其他 OpenCode 进程会在下一次插件动作时读取新状态。

总开关关闭后：

- 不向模型系统提示注入 Memory、用户画像或 learned Skill 索引。
- 不在会话空闲时检查或启动自动复盘。
- `/learn`、`/learn-review` 以及 Memory/Skill 工具不再读写学习数据。
- `learning_mode` 和 `learning_status` 仍保留，以便查看状态或重新开启。
- 已保存的数据不会被删除，重新开启后继续使用。

“在对话中使用记忆”是独立开关。关闭它以后，普通对话不再自动注入全局 `MEMORY.md`、`USER.md`、当前项目 Memory 和 learned Skill 索引，但学习、自动复盘和落盘仍可继续；已经保存的数据不会删除。重新开启后，后续对话会再次使用这些记忆。

## 4. 主动学习和复盘

学习一个可复用主题：

```text
/learn 如何在这个项目中可靠地执行数据库迁移
```

立即复盘当前会话：

```text
/learn-review
```

`/learn` 会让当前 Agent 先调查和验证，再创建或更新一个用户所有的 Skill。`/learn-review` 只复盘当前会话中已经完成并验证的内容。模式关闭时，这两个命令不会写入数据。

## 5. 自动复盘

自动复盘同时要求：

1. 总开关 `enabled` 为 `true`。
2. 自动复盘开关 `autoReview` 为 `true`。
3. 自上次成功复盘后，累计达到用户回合数或工具调用数阈值。

默认是累计 10 个用户回合或 15 次已完成/失败的工具调用后触发。后台会创建隔离子会话，只允许 `learning_memory`、`learning_skill` 和 `learning_status`，完成后删除内部会话。

自动复盘会产生模型调用和相应额度消耗。只想主动学习时，可保持总开关开启，同时把 `autoReview` 设为 `false`。

## 6. 配置项说明

配置位置：

```text
~/.config/opencode/continuous-learning/config.json
```

默认配置：

```json
{
  "enabled": true,
  "memoryContextEnabled": true,
  "autoReview": true,
  "memoryEveryTurns": 10,
  "skillEveryToolCalls": 15,
  "retryCooldownMinutes": 30,
  "maxConcurrentReviews": 2,
  "maxTranscriptChars": 60000,
  "memoryCharLimit": 2200,
  "projectMemoryCharLimit": 4000,
  "userCharLimit": 1375,
  "foregroundWriteApproval": true,
  "deleteReviewSessions": true,
  "showNotifications": true
}
```

| 配置项 | 默认值 | 合法范围 | 作用 |
| --- | ---: | --- | --- |
| `enabled` | `true` | 开/关 | 持续学习模式总开关 |
| `memoryContextEnabled` | `true` | 开/关 | 是否把 Memory、用户画像和 Skill 索引自动注入对话 |
| `autoReview` | `true` | 开/关 | 是否允许后台自动复盘 |
| `memoryEveryTurns` | `10` | 1–1,000 | Memory 复盘的用户回合阈值 |
| `skillEveryToolCalls` | `15` | 1–10,000 | Skill 复盘的工具调用阈值 |
| `retryCooldownMinutes` | `30` | 1–1,440 | 自动复盘失败后的重试冷却分钟数 |
| `maxConcurrentReviews` | `2` | 1–8 | 同时运行的后台复盘上限 |
| `maxTranscriptChars` | `60000` | 4,000–500,000 | 送入复盘会话的最大转录字符数 |
| `memoryCharLimit` | `2200` | 500–100,000 | 全局 `MEMORY.md` 最大字符数 |
| `projectMemoryCharLimit` | `4000` | 500–100,000 | 每个项目 Memory 的最大字符数 |
| `userCharLimit` | `1375` | 500–100,000 | `USER.md` 最大字符数 |
| `foregroundWriteApproval` | `true` | 开/关 | Agent 前台写入或切换模式时是否请求权限 |
| `deleteReviewSessions` | `true` | 开/关 | 自动复盘完成后是否删除内部会话 |
| `showNotifications` | `true` | 开/关 | 是否显示成功、失败等通知 |

推荐使用设置面板。也可以直接编辑 JSON 文件；保存后各 OpenCode 进程会在下一次插件动作时自动重载。配置文件中的插件未知字段会在面板修改和恢复默认值时保留，便于以后版本升级。

常见组合：

- 完全关闭：`enabled = false`。
- 继续学习但不让历史记忆影响普通对话：`enabled = true`、`memoryContextEnabled = false`。
- 只主动学习、不后台调用模型：`enabled = true`、`autoReview = false`。
- 开启全部能力：`enabled = true`、`memoryContextEnabled = true`、`autoReview = true`。

## 7. 数据位置

```text
~/.local/share/opencode/continuous-learning/MEMORY.md
~/.local/share/opencode/continuous-learning/USER.md
~/.local/share/opencode/continuous-learning/projects/<项目名>-<路径哈希>/MEMORY.md
~/.local/share/opencode/continuous-learning/review-state.json
~/.local/share/opencode/continuous-learning/skill-provenance/
~/.config/opencode/skills/<name>/SKILL.md
```

`learning_memory` 的 `user` 目标保存身份和长期偏好，`memory` 只保存跨项目环境事实与约定，`project` 保存当前项目的架构、命令、约束和持久决策。项目分区按项目根目录的规范化绝对路径生成，当前会话不会注入其他项目的内容。前台主动创建或修改的 Skill 属于用户，后台不能覆盖。后台只能继续修改由后台创建且没有被用户手工改动的 Skill。

新 Skill 可立即通过 `learning_skill view` 读取；要让 OpenCode 原生 `skill` 工具重新建立完整索引，建议重启 OpenCode。

## 8. 安全和隐私

- 不要把令牌、密码、私钥或临时凭据保存为 Memory 或 Skill。
- 插件会扫描常见凭据和提示注入特征，但扫描不能替代人工判断。
- 模式开启时，Memory、用户画像和 Skill 索引会进入模型上下文。
- 模式关闭后不再注入这些内容，但磁盘上的历史数据会保留。

## 9. 排查问题

先查看状态：

```text
/learning-settings
```

也可以让 Agent 调用 `learning_status`，检查配置、存储路径、条目数量和复盘检查点。

终端验证插件是否加载：

```bash
opencode debug agent continuous-learning-review
```

正常情况下，隐藏 Agent 只有 `learning_memory`、`learning_skill` 和 `learning_status` 为可用状态。如果命令列表或工具没有更新，完全退出并重新启动 OpenCode。

如果 `/learning-settings` 没有出现：

1. 运行 `opencode --version`，确认版本不低于 1.18.15。
2. 重新执行本项目的 `scripts/install.sh` 或 `scripts/install.ps1`。
3. 检查 `~/.config/opencode/tui.json` 的 `plugin` 数组中是否保留了持续学习本地插件路径。
4. 完全退出所有 OpenCode 进程后重新启动。

安装脚本会在 `~/.config/opencode/continuous-learning/install-backups/时间戳/` 备份被替换的插件文件、命令、手册和原有 `tui.json`。
